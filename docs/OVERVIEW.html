프로젝트 개요 · 2026-07-23 개정

대화로 완성하는
AX 웹 제너레이터

기획 내용을 대화로 입력하면, 선택한 스타일 팩으로 웹페이지를 생성·수정·관리한다. 온사이트는 첫 번째 스타일 팩일 뿐 — 제너레이터 자체는 스타일 중립이다.

✓ 제너레이터 엔진 완료 ▢ 팩·템플릿·섹션 저작 중 ✦ NL 프론트도어 · 팩 3+ (~10월)
01

무엇을 만드는가

핵심은 하나의 불변식 — 앞문(입력 방식)이 바뀌어도 뒷문(PageDoc·렌더러)은 고정이다. 사람이 대화로 채우든, 나중에 AI가 자연어로 채우든, 렌더러는 똑같은 PageDoc을 받는다. 이 분리 덕분에 입력 UX는 계속 진화해도 출력 품질은 흔들리지 않는다.

🚪 앞문 — 입력

대본형 대화로 정해진 질문에 값만 채운다(이해·추론 0 = 무료). 섹션을 채우면 그 자리가 실시간으로 렌더 → "AX가 만들어주는" 느낌.

  • 프로젝트: 종류 · 스타일 팩 · 공유 사실
  • 페이지마다: 타입 → 볼륨 → 섹션 값

🏛️ 뒷문 — 렌더 (고정)

PageDoc = 단일 진실원본(SSOT). 스타일 팩이 디자인을 잠그고 사용자는 콘텐츠만 연다 → "아무나 만져도 안 망가지는" 품질 보증.

  • 생성 = 조립(규칙) ≠ 추론(AI)
  • 출력: 깔끔 HTML/CSS → 보기·개발·Figma 변환
투 트랙 전략. A) 제너레이터(기계)는 개발용 비계 팩으로 먼저 만들고 — 지금 여기까지 왔다. B) 온사이트 실측 DS를 추출해 "진짜 팩"으로 교체. 두 트랙은 DS 팩 규격(8개 범위)에서 만나고, 팩이 교체 가능하므로 특정 DS에 종속되지 않는다(멀티팩).
8
스타일 팩이 정의하는 범위 (토큰·그리드·컴포넌트·variant·시그니처·모션·그래픽키트·다크모드)
1
생성 엔진 = 단일 페이지. 다중은 반복 + 관리 층
0
MVP 런타임 AI 비용 — 전부 결정론적 조립
3
모션 다이얼: 정적 / 은은 / 리치 (팩·구조와 독립 층)
02

누가 쓰고, 우리는 무엇을 하나

제품을 대신 만들어 주는 게 아니라 — 기획자·사업 담당자가 셀프로 뽑게 한다. 우리는 팩과 플랫폼을 관리한다.

🎯 대상

기획자 · 사업 담당자. 개발/디자인 리소스 없이 온브랜드 사이트가 필요한 사람. "디자인 잠금·콘텐츠 개방"이 정확히 이들을 위한 설계.

🛠️ 우리 역할

디자인 팩 관리 + AX 플랫폼 고도화. 사이트를 만드는 건 사용자, 우리는 재료(팩)와 엔진(플랫폼)을 책임진다.

🏢 배포 확장

단일 URL(MVP) → 법인/조직 멀티테넌트. 각 법인이 산출물을 자기 서버에 올려 MBM·사이트 구축에 활용. 국내·해외·법인 셀프서비스가 확장 축.

🌐 로컬라이징 지금 착수 가능

1차 언어 한국어 · 영어 · 일본어 · 중국어. 리스크 낮고 구조 영향 적어 근시일 착수 가능.

  • 산출물 다국어(핵심) — 같은 PageDoc에 언어별 슬롯값 → 언어 전환. 레이아웃·팩 공유(CJK+라틴 폰트만 고려)
  • 앱 UI 다국어(부차) — 대본 문구·라벨을 i18n 키로 분리

🔐 준비돼야 할 거버넌스 후속

전사·법인 확장 시. MVP는 0으로 가되 얹힐 자리를 지금 구조에 비워 둔다(프로젝트=테넌트 경계, AI 콜=미터링 지점).

  • 권한/역할 — 조직·프로젝트별 뷰어/편집/관리, 팩 접근 범위
  • 토큰 사용(미터링) — 조직별 예산 상한·사용량 계량·과금 경계
  • 테넌시·인증 — 조직 분리 저장(BaaS), SSO(필요 시)
03

지금 어디까지 왔나

"제너레이터 먼저, 팩 나중" 전략이 적중했다. 플로우를 실제로 만들며 어떤 정보를 받아 어떻게 보여줄지가 확정됐고 — 그 결과 빈칸 채우기식 제너레이터 엔진은 완료. 예상보다 빠르게 MVP 엔진에 도달했다. 남은 것은 지능이 아니라 재료(팩·템플릿·섹션)다.

MVP 진척 — 엔진 vs 자산엔진 ≈ 완료 · 자산 착수
완료 — 엔진

앞문/뒷문 파이프라인

  • 프로젝트 생성 (종류·스타일·공유 사실)
  • 대본형 대화 입력 + 슬롯 위젯
  • 실시간 섹션 프리뷰
  • 빌더: 인라인 텍스트·이미지 교체, 섹션 순서/숨김
  • 다중 IA: 레일 트리 → 네비 자동생성 → GNB 반영
  • 관리: 대시보드·목록·필터·검색·다중삭제
  • 템플릿 갤러리 → 생성·편집 진입
  • 미리보기 새 창 · HTML/JSON 출력
  • 앱 셸 DS (라이트/다크·디자인 모달)
남음 — MVP 완성

지능 아님, 재료 채우기

  • 페이지 타입 카탈로그 + 템플릿 정식화
  • 섹션 빈 곳 채우기 (매뉴얼 toc·체인지로그·요금 상세)
  • 온사이트 팩 실측 추출 (트랙 B)
  • 섹션 slotSchema(JSON) 정식화
  • 팩 3종은 아직 비계 — 진짜 팩으로 교체 필요
새 방향

고도화 일부를 앞당김

  • NL 프론트도어: 생성 시 자연어+파일 → AI 초기 판단
  • 섹션 variant 랜덤 조립 (타입당 2~3, 디자인은 고정)
  • 디자인 팩을 AI로 저작-타임 다수 생성
  • 부족하면 좌측 대화가 대본형으로 이어받음
04

개정된 파이프라인

기존 대본 대화는 그대로 두고, 그 앞에 자연어 진입 한 겹을 얹는다. AI는 디자인이 아니라 구조 판단에만 개입한다 — 카탈로그 안에서만 선택하므로 새 페이지·새 섹션을 창작하지 않는다.

0
자연어 입력 + 파일 첨부 NEW · AI 1콜
"협업 캘린더 제품 소개 사이트, 기능·요금·문의 페이지 필요" + 기획서 드롭 → 싼 모델이 단/다·IA·섹션 후보를 JSON으로 판단. 카탈로그는 프롬프트 캐싱.
1
초기 셋팅 자동 구성
레일·페이지·섹션 스캐폴드 생성. 결과는 편집 가능 — AI는 초안, 결정은 사람.
2
좌측 대화 패널 — 값 채우기
정보 부족하면 여기서 되물음. NL(있으면) + 대본(항상) 하이브리드 — NL은 편의층, 대본은 안전판.
3
조립 + 섹션 variant 랜덤 결정론 · AI 0
팩이 사전 저작한 표현형 2~3개 중 규칙적 랜덤 선택 → 단조로움 완화. 디자인 자유도는 여전히 0.
4
프리뷰 → 빌더 → 출력
실시간 프리뷰, 콘텐츠·구조 편집, 깔끔 HTML/CSS 내보내기(단일=1파일 · 다중=폴더+zip).
디자인엔 AI를 넣지 않는다 — 처음엔. 다양성은 지능이 아니라 탑재 자산의 폭에서 나온다. 재료(팩·variant·그래픽 키트)를 많이 만들어 두고 긁어와 조립하는 형태. 자유도를 주지 않는 대신 항상 온브랜드·품질 보증.
05

앞으로 어떻게

근시일은 주차 단위로, 큰 그림은 분기로. AI 개입은 한 번에 뛰지 않고 사다리로 올린다 — 아래로 갈수록 자유↑ / 통제·비용·리스크↑.

토큰 비용 계획

MVP 운영비는 사실상 0. 런타임 AI는 진입 판단 1콜(캐싱된 카탈로그) + 선택적 되물음뿐이고, 나머지(조립·variant·렌더·출력)는 전부 결정론적이다. 대가는 돈이 아니라 사전 저작 노동이다.

항목내용비용 관리
진입 판단 1콜자연어+파일 요약 → 단/다·IA·섹션 JSON. 싼 모델(Haiku급), 입력 수 K·출력 <1K프로젝트당 1회 · 센트 미만
카탈로그 컨텍스트페이지타입·섹션 메뉴를 프롬프트에 동봉(선택지 제약)프롬프트 캐싱 → 거의 무료
