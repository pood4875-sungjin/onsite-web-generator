사용자 여정 (전체 흐름)

  1. 인테이크(자료 접수) — 홈 화면에서 대화하듯 자료를 넣는다. PPT·워드·PDF를 끌어다 놓으면 어디로 업로드되는 게 아니라 브라우저가 그 자리에서 파일을 열어 내용을 읽는다 (파일 여는 부품 3종이 app/vendor/에 내장 — 인터넷 막힌 사내망에서도 첨부 동작). 이어서 AI 중계 서버(워커 — 클라우드에 떠 있는 작은 심부름 서버)가 자료를 요약하고 부족한 정보를 되묻는다. 이 단계는 빠른 모델(haiku)을 써서 몇 초면 끝난다. 되묻는 카드 중에 분량과 화면 비율(16:9 · 4:3 · 3.8:1)도 있다 — 비율은 스타일 카드보다 먼저 물어야 썸네일이 그 비율로 그려진다.
  2. 생성 — 워커에 주문이 접수된다. 주문 창구가 결과물별로 나뉘어 있어서 PPT는 /compose, 랜딩은 /compose-web이라는 창구를 쓴다(이름은 외울 필요 없음 — 고장 신고 때 에러 메시지에 떠서 어느 창구 문제인지 알려주는 표지판). AI가 써 내려가는 내용을 실시간으로 흘려받아 장표가 한 장씩 눈앞에서 그려진다.
  3. 스튜디오 편집 — 채팅으로 수정("3장 제목 바꿔줘"), 장표 위를 클릭해 글자를 그 자리에서 고치는 인라인 편집, 이미지 피커(AI 이미지 생성 포함), 섹션 순서변경·숨김. 화면 비율도 상단 스위처로 만든 뒤에 바꿀 수 있다.
  4. 번역 — 한국어·영어·일본어·중국어 4개 언어 전환. 3장씩 잘라 병렬 번역.
  5. 발표 대본 — 🎤 버튼. AI가 장표별 대본·시간·전환멘트 작성(진행바 실시간 표시).
  6. 추출/공유 — 완성본을 PPTX 파일로 내려받거나 링크 하나로 공유한다. 내려받는 PPTX는 고른 화면 비율 그대로 나간다(파워포인트에서 열었을 때 지면 크기가 맞는다). 공유 시엔 내 컴퓨터에만 있는 이미지 경로를 인터넷에서 열리는 주소로 자동 교체한다 (안 하면 받는 사람 화면에서 이미지가 깨져서).
화면 비율 3종 — 지면 크기 고르기
PPT는 지면 비율을 16:9(와이드·기본) · 4:3(클래식) · 3.8:1(초와이드) 중에서 고른다. 생성 전에는 인테이크 카드에서, 생성 후에는 스튜디오 상단 스위처에서 언제든 바꾼다 — 바꾸면 본문·썸네일이 다시 그려진다. PPTX로 뽑을 때도 그 규격이 그대로 따라간다.

비율이 없는 옛 프로젝트는 자동으로 16:9로 본다(하위호환). 규격의 원본 문서는 docs/RATIO_CONTRACT.md — 새 PPT 팩을 만들 땐 여기 체크리스트를 따라야 한다.

기술 정체성 — "조립 공정이 없다"
보통 웹 프로젝트는 코드를 완성품으로 바꾸는 조립 공정(빌드)을 거치는데, 이 프로젝트는 그 공정이 아예 없다. 폴더 안의 파일이 곧 완성품이라 파일을 고치고 새로고침하면 결과가 바로 보인다 (전문 용어로 buildless — 빌드 도구·프레임워크 없이 클래식 <script>만 사용). 비개발자도 다룰 수 있게 하려는 의도된 설계이니 이 단순함을 지키길 권장.

용어 사전 — 막히면 여기로 돌아온다

이 문서에 나오는 개발 용어를 전부 한 줄로 풀었다. 지금 외울 필요 없다. 읽다가 모르는 말이 나오면 이 표로 돌아오면 된다. 정확한 명칭은 괄호에 남겨 뒀다 — 클로드에게 말할 땐 괄호 쪽 단어를 쓰면 더 정확히 알아듣는다.

요청 패턴 — 실제로 이렇게 시켰다

대화는 전부 한국어, 개발 용어 없이 했다. 클로드가 알아서 기술로 옮긴다. 실제로 반복된 패턴 4가지:

패턴 1 — 소스 주고 실측 요구
"이 PDF(네이버스타일.pdf) 그대로 PPT 팩으로 만들어줘. 소스에 있는 것만, 추측하지 말고."

→ 팩 제작의 기본형. "추측 금지"가 붙으면 Claude는 소스에 없는 값을 만들지 않고, 막히면 멈추고 물어본다.

패턴 2 — 증상 그대로 신고
"생성이 하다 말아" / "번역이 안 돼" / "일본어 글자가 얇아 보여" / "이미지가 사라졌어"

→ 원인을 짐작해 말할 필요 없다. 증상만 말하면 debug-generation 절차서가 AI 서버 → 브라우저 → 화면 순서로 층을 하나씩 짚어 범인을 좁힌다.

패턴 3 — UX 감각 전달
"기다리는 과정이 조금 보여도 좋구. 프로그레스라던지" / "3.8:1은 레이아웃이나 여백이 벙벙한데 디자인적으로 조정 잘 해줬으면"

→ 감각·의도 수준의 요청도 됨. 전자는 대본 생성 진행바가, 후자는 초와이드 비율의 레이아웃 재설계가 됐다.

패턴 4 — 규칙 선언 (한 번 말하면 영구 반영)
"push는 내가 말할 때만 해" / "API 키는 채팅에 절대 안 붙일 거야" / "완료되면 비유로 설명해줘"

검증 문화 — "될 겁니다" 금지

이 프로젝트에서 가장 중요한 문화. AI가 "고쳤어요, 될 겁니다"라고 말로만 끝내는 것을 금지하고, 항상 실제로 돌려본 증거를 보여달라고 했다:

  • AI 서버를 고쳤으면 — 진짜 주문을 하나 넣어보고 답이 제대로 오는지 확인한다 (터미널에서 서버를 직접 불러보는 curl이라는 도구 사용)
  • 화면을 고쳤으면 — 임시 시험 페이지(_verify…html)를 만들어 브라우저에 띄우고 스크린샷으로 확인한다. 시험 페이지는 확인이 끝나면 삭제(폴더에 쓰레기 안 남기기)
  • 이미지·디자인은 눈으로 — 클로드가 스크린샷을 찍어 보여주면, 사람이 원본과 나란히 놓고 대조한다
  • 코드를 고쳤으면 — 오타 검사기(node --check)부터 돌려 문법 실수를 걸러낸다

이 습관은 나중에 자동화됐다 — "검증해줘" 한 마디면 위 과정을 알아서 도는 절차서(verify-e2e 스킬)가 생겼고, 저장(커밋)할 때마다 검사기가 자동으로 돌아서 불합격이면 저장 자체가 막힌다(§9의 커밋 자동 검수).

05팩 시스템 (이 프로젝트의 핵심)

철학 — 팩은 잉크 카트리지

앱은 "프린터", 팩은 "잉크 카트리지". 같은 내용(자료)이라도 팩만 바꾸면 완전히 다른 스타일로 출력된다. 그래서 팩 하나에 색·글꼴·간격부터 부품 모양·그리는 방식·등장 애니메이션·PPTX로 뽑는 규칙까지 전부 들어 있다 (파일 하나로 자기완결). 앱은 팩을 갈아끼우고 자료를 넘겨주는 얇은 진행자일 뿐이다 — 디자인 판단은 전부 팩 안에서 끝난다.

덕분에 부수 효과가 하나 생겼다. 팩 파일(.js)과 짝꿍 설명서(.md)만 꺼내서 다른 도구나 다른 AI 대화에 첨부하면 스타일이 그대로 옮겨간다. 팩 = 재사용 가능한 디자인 자산.

왜 팩을 js(코드 파일)로 만들었나 — md(문서)로는 안 되나?
역할이 달라서 둘 다 쓴다. md는 레시피 카드 — 무슨 색·글꼴·간격인지 사람과 AI가 읽는 설명서. 읽을 수는 있지만 뭔가를 만들어내진 못한다. js는 요리사 — 재료(제목·문장·수치 데이터)를 받으면 실제로 화면을 만들어내는 실행 기계다. 브라우저는 md를 실행하지 못하고 js만 실행할 수 있어서, "실제로 그리는 일"은 js여야만 한다. 그래서 모든 팩이 packs.X.js(요리사)+packs.X.md(레시피) 짝꿍 구조 — 스타일만 다른 도구에 이식할 땐 md를 첨부하고, 이 앱에서 실제로 돌릴 땐 js까지 쌍으로 가져간다.

PPT 팩 하나를 열어보면 — 6층 + 비율

파일 하나(packs.X.js) 안에 아래가 순서대로 들어 있다. 위쪽이 "무엇으로 그리나", 아래쪽이 "어떻게 내보내나".

웹 팩은 두 갈래다 — 랜딩형(골격 고정)과 사이트형(조립식)

① 랜딩·집객형(Civil Blue·Ensol MBM·Global MBM·Toss 등) — 완성된 페이지 골격이 통째로 정해져 있고 그 안의 글자·이미지만 갈아 끼운다. 행사·프로모션 랜딩은 정체성이 강해서, 자유롭게 조립하게 두는 것보다 골격을 고정하는 쪽이 결과가 훨씬 좋았기 때문이다. 섹션은 순서변경·숨김·추가만 허용한다.

② 사이트형(Saturn 블루·KRDS·MIDAS AX·Aether Glass) — PPT 팩과 같은 조립식이다. 공용 페이지 유형표(app/pagetypes.js — 메인홈·제품소개·요금·FAQ 등 10유형)가 "이 페이지엔 이런 섹션 순서"를 정하고, 팩은 히어로·기능·프라이싱·FAQ·폼 같은 섹션 어휘 21종의 렌더러를 자기 디자인으로 구비한다. 여러 페이지짜리 웹사이트(GNB 메뉴·페이지 연동 포함)는 이 갈래만 가능하다.

정확한 구조: 두 갈래 모두 renderXPage(shared, {volume, motion})가 완성된 페이지 HTML을 통째로 반환. 랜딩형은 섹션 순서변경·숨김·추가를 X_SECTION_SPEC으로 앱에 노출하고, 사이트형은 데이터의 pageType을 보고 유형표대로 섹션을 조립한다.

⚠ 그래서 홈 화면 스타일 목록도 종류별로 다르다 — 랜딩(한 장)을 고르면 랜딩형 팩, 웹사이트(여러 페이지)를 고르면 사이트형 팩이 나온다. 랜딩형 팩을 웹사이트에 물리면 "모든 페이지가 같은 템플릿·GNB 연동 없음"이 되는 사고가 난다(2026-08-12 실제로 겪고 종류별로 분리해 둠).

07AI 배선 — 워커 (proxy/worker.js)

AI에 대한 결정권은 전부 서버(워커)에 있다. AI에게 주는 지시문, 어떤 모델을 쓸지, 한 번에 얼마나 길게 쓸지 — 전부 proxy/worker.js 한 파일 안이다. 브라우저 쪽 코드를 누가 손대도 결과 품질이 흔들리지 않는 구조다. 그리고 API 키는 이 서버의 금고에만 있다 — 코드에도, 이 폴더에도, 브라우저에도 없다.

아래 "창구"는 정확히는 라우트라고 부른다. 하나의 서버가 여러 창구를 두고 용건별로 다른 접수를 받는 것이라고 보면 된다. 이름을 외울 필요는 없고, 고장 신고 때 에러 메시지에 떠서 어느 창구가 문제인지 알려주는 표지판 역할을 한다.

발표용 고정(시연 잠금)은 어떻게 만들어져 있나

지금은 전부 풀려 있다(2026-08-11). 다만 다시 걸 수 있게 구조가 남아 있다.

팩마다 AI 지시문이 두 벌이다. 현재 쓰는 자유 구성본(NAVER_SYSTEM 같은 이름)과, 발표 때 쓰던 고정본(이름 끝에 _LOCKED가 붙은 것). 고정본은 "정확히 10장, 이 순서, 이 문구"까지 못 박아 둔 지시문이다. 다시 고정하려면 두 이름을 맞바꾸면 끝이라 복원이 안전하다. 팩 파일 쪽에도 문구를 강제로 덮어쓰는 함수(lockDemo)가 호출만 꺼진 채 남아 있다.

전체 절차는 demo-lock 절차서에 있다. 클로드에게 "시연 잠금 걸어줘"라고 하면 그대로 따라간다. 이 잔재를 지우지 말 것 — 지우면 다시 만들어야 한다.

키·사용량 관리

  • 키 등록·교체는 사람이 직접 한다 — 터미널에서 cd proxy && npx wrangler secret put ANTHROPIC_API_KEY 를 실행하거나 Cloudflare 대시보드에서. 키를 채팅창에 붙여넣지 않는 것이 원칙이고, 클로드도 키를 요구하지 않게 설정돼 있다.
  • 하루 호출 한도(DAILY_LIMIT)가 예상 밖 과금을 막는 안전핀이다. 지금은 시연용으로 999까지 올려 둔 상태 → 운영 전환 시 되돌릴 것(§12).

08다국어 — 4개 언어 (ko·en·ja·zh)

번역할 것이 두 겹이라 헷갈리기 쉽다. 하나는 앱 자체의 말(버튼·메뉴 — 미리 만들어 둔 사전으로 교체), 다른 하나는 만들어낸 결과물의 내용(장표·사이트 본문 — AI가 그때그때 번역). "영어로 바꿨는데 한국어가 남아 있다"는 신고가 오면 둘 중 어느 겹인지부터 가려야 한다.

겹 ① 앱의 말 — 미리 만든 사전

app/i18n.js에 '한국어 문구' → [영어, 일본어, 중국어] 짝이 통째로 들어 있고, 화면의 글자에 표식을 달아두면 언어를 바꿀 때 그 자리에서 갈아 끼운다. 새 문구를 화면에 추가했으면 사전에도 등록해야 한다 — 안 하면 영어 화면에 그 버튼만 한국어로 남는다. 빠진 게 없는지 검사하는 도구가 scripts/check-i18n.cjs.

겹 ② 결과물의 내용 — AI 번역

순서는 이렇다. ①무거운 이미지 데이터를 먼저 뺀다(안 그러면 분량 초과로 통째 실패) → ②3장씩 잘라 동시에 번역(빠르다) → ③번역된 글자만 원본에 다시 끼워 넣는다(이미지·설정은 원본 유지) → ④회사 표기법을 자동 교정. 실패하면 부분·전체 각각 한 번씩 자동으로 재시도한다.

번역 실패 3대 전과 — 재발하면 여기부터 의심
① 업로드한 이미지가 통째로 짐에 섞여 분량 초과 → 이미지를 먼저 빼는 처리로 해결
② 한 번에 쓸 수 있는 길이를 줄였다가 웹 번역이 중간에 잘림 → 원래 값(16000)으로 복원
③ AI가 결과를 한 겹 더 감싸서 줄 때도 있고 아닐 때도 있었다(빠른 모델이 지시를 흘림) → 양쪽 다 받아들이게 수정
중국어·일본어 글꼴 함정
기본 글꼴(Pretendard)이 흔한 한자를 일부만 갖고 있다. 그래서 한 문장 안에서 글자마다 글꼴이 달라 보인다 → 중국어·일본어는 Noto Sans SC/JP를 1순위 글꼴로 지정해 해결. 그리고 가는 굵기(300)는 한자에서 실낱처럼 보여서 → 랜딩 500 · PPT 400으로 올렸다. 이미 전 팩에 적용돼 있다.
언어 꼬리표(_clang) — 사고 최다 지역
프로젝트마다 "이 결과물은 무슨 언어다"라는 꼬리표가 붙어 있다(_clang). 문제는 화면이 그려지는 길목이 네 군데(본문·썸네일·생성 중 미리보기·공유 뷰어)라는 것. 한 군데라도 꼬리표를 안 딸려 보내면 목록과 본문의 언어가 어긋난다 — 실제로 여러 번 났다. 새 렌더 경로를 만들면 꼬리표 동봉을 반드시 확인할 것.

그리고 고정 문구의 언어를 정할 땐 꼬리표보다 내용이 우선이다. 영어 덱에 한국어 인명 몇 글자가 있다고 한국어로 판정하면 안 되므로 비율로 따진다.

10배포 — "푸시 ≠ 배포"

가장 자주 오해하는 부분이다. 이 프로젝트는 GitHub에 올린다고 사이트가 갱신되지 않는다. 푸시는 온라인 보관소에 백업하는 것이고, 배포는 인터넷 주소에 올려 남들이 보게 하는 것 — 완전히 다른 일이다. 배포는 아래 명령을 직접 실행해야 일어난다.

# ① 사이트 (폴더 맨 위에서 실행)
npx wrangler pages deploy . --project-name=midas-drs --commit-dirty=true

# ② AI 중계 서버(워커)
cd proxy && npx wrangler deploy

둘은 별개다. 화면만 고쳤으면 ①만, AI 지시문을 고쳤으면 ②만 하면 된다. 클로드에게 "배포해줘"라고 하면 어느 쪽이 필요한지 판단해 실행하고, 실제로 떴는지까지 확인한다.

  • 배포 직후엔 반영에 30초쯤 걸린다. 바로 확인해서 안 바뀌었다고 놀라지 말 것 — deploy 절차서가 이 대기와 확인까지 처리한다.
  • 내 컴퓨터에서 확인하는 두 방법: ① python3 serve.py로 서버를 띄우고 접속(기본 포트 4788, 이전 파일을 기억하지 않게 설정돼 있음) ② app/index.html 파일을 브라우저로 그냥 열기. ②는 파일을 고치는 즉시 반영되지만, 브라우저가 옛 파일을 기억하고 있어서 강력 새로고침(⌘+Shift+R)이 필요하다.
  • 커밋은 내 컴퓨터까지만. 푸시는 사람이 명시적으로 요청할 때만 — 클로드도 그렇게 설정돼 있다.

인계자가 자기 것으로 갈아끼우는 3단계

인계자는 받자마자 테스트해야 한다. Cloudflare를 쓸지 말지는 나중에 정해도 되고, 아래 순서로 올라가면 된다. 실측 확인: 아래 T1은 브라우저에서 실제로 전환되는 것까지 확인했다(설정 화면에 API 키 입력창이 나타남).

단계필요한 것되는 기능방법
T0. 그냥 열기
0분		 없음 기존 프로젝트 열람·편집·PPTX 내려받기·스타일 구경. AI 생성 ✕ python3 serve.py 후 접속. 넘기기 전 --clean을 돌렸다면 AI만 꺼져 있는 상태
T1. 자기 API 키만
5분 · 권장 시작점		 본인 Anthropic 키 PPT·웹 생성, 채팅 수정, 번역, 화면 비율 전부 ○
발표 대본·AI 이미지 ✕(중계 서버가 있어야 되는 기능)		 설정 화면 → API 키 입력 → 저장. Cloudflare 전혀 불필요
T2. 자기 Cloudflare
30분		 Cloudflare 계정 + 키 2개 전 기능 — 대본·AI 이미지·공유 링크 포함 아래 B 8단계
파일을 안 고치고 AI 서버를 끄거나 바꾸는 스위치
브라우저 개발자 도구의 콘솔(명령 입력창)에 한 줄만 치면 전환된다 — 코드를 건드릴 필요가 없다. 
localStorage.setItem('onsite-ai-proxy','off')          // 중계 서버 끄기 → 각자 자기 키를 쓰는 모드
localStorage.setItem('onsite-ai-proxy','https://내워커...')  // 내가 배포한 서버로 연결
localStorage.removeItem('onsite-ai-proxy')             // 원래대로

입력 후 새로고침하면 적용된다. 여러 명이 각자 다른 키로 테스트할 때 유용하다. (콘솔 여는 법: F12 또는 ⌘+⌥+I → Console 탭)

A. 키만 회사 것으로 교체 (5분 — 과금 이전은 이걸로 끝)

계정·주소는 그대로 두고 돈 나가는 주체만 바꾸는 방법. 회사에서 Anthropic 키와 Google AI Studio(Gemini) 키를 발급받은 뒤:

cd proxy
npx wrangler secret put ANTHROPIC_API_KEY   # 실행하면 입력창이 뜸 — 거기에 회사 키 붙여넣기
npx wrangler secret put GEMINI_API_KEY
npx wrangler deploy

터미널이 필수는 아니다. Cloudflare 대시보드에서도 된다: Workers & Pages → webgen-ppt-proxy → Settings → Variables and Secrets → 해당 secret Edit → 새 키 붙여넣기 → Save. 결과는 위 명령과 동일하다(대시보드는 저장 즉시 반영돼 재배포 불필요).

키 취급 원칙
키는 채팅·코드·레포 어디에도 붙여넣지 않는다 — 터미널 입력창이나 대시보드 입력칸에만. Claude에게 "키 교체할래"라고 하면 위 절차를 안내해 주고, 키 자체는 절대 요구하지 않는다(그렇게 세팅돼 있음).

B. Cloudflare 계정까지 통째 이관 (회사 계정으로)

Claude에게 "회사 Cloudflare 계정으로 이관하자"라고 하면 아래 순서로 같이 진행된다:

  1. 회사 계정으로 npx wrangler login
  2. 보관함(KV) 2개 새로 만들기(wrangler kv namespace create RATE_KV / PUB) → proxy/wrangler.toml의 id 교체 — 각각 호출 횟수 세기용·공유 링크 보관용
  3. Cloudflare 대시보드에서 AI 게이트웨이 "webgen" 생성 — Anthropic이 홍콩 등 일부 지역에서 온 요청을 막기 때문에 이 우회 통로를 거쳐 나간다. 빼먹으면 한국에서 간헐적으로 거부(403)당한다
  4. proxy/worker.js의 ACCOUNT_ID(643행)를 본인 Cloudflare 계정 ID로 교체 — 위 게이트웨이 주소에 쓰인다. 계정 ID는 대시보드 우측 사이드바 또는 npx wrangler whoami로 확인
  5. cd proxy && npx wrangler deploy → 새 워커 주소가 나옴
  6. secret 2개 등록(위 A 명령)
  7. app/llm.js 상단 PROXY_URL을 새 워커 주소로 교체 — 교체 지점은 이 한 곳뿐(파일에 주석으로 표시해 둠)
  8. Pages 새 프로젝트로 사이트 배포: npx wrangler pages deploy . --project-name=새이름
  9. 내 사이트 주소(midas-drs.pages.dev)가 코드에 글자 그대로 박혀 있는 곳을 전부 새 주소로 교체 — 이미지가 안 열릴 때의 대체 경로·공유 링크용으로 5개 파일(스튜디오 + 팩 4종)에 들어 있다. 클로드에게 "프로드 주소 ○○로 전부 바꿔줘" 하면 교체와 확인까지 해준다. 직접 찾으려면: 
    grep -rln "midas-drs.pages.dev" app/ packs/ --include="*.js" --include="*.html"
이관하면 잃는 것 — 기존 공유 링크
이미 뿌린 공유 링크는 옛 계정의 보관함에 들어 있어서(90일 보관) 계정을 옮기면 전부 안 열리게 된다. 살아 있는 공유 링크가 중요한 기간(시연 등)을 피해서 이관할 것.

C. 실제 인계 시나리오 — 상황별로 이 중 하나

상황할 일내 계정에서 나가는 돈
① 서비스는 계속 살려두고 인계자만 개발
(가장 흔한 경우)		 폴더/GitHub만 넘김. 워커·Pages는 그대로. 인계자는 배포 권한만 받으면 됨(Cloudflare 계정 초대 또는 배포는 나에게 요청) 계속 나감 — 그래서 A(키 교체)를 같이 하는 게 맞다
② 과금만 회사로
(권장 · 5분)		 폴더 넘김 + A(secret 2개를 회사 키로 교체). 주소·계정은 그대로라 사용자는 아무 변화 못 느낌 0원 — Cloudflare 무료 티어만 남음
③ 완전 분리
(내 계정과 인연 끊기)		 폴더 넘김 + B 8단계(회사 Cloudflare로 워커·Pages·KV 재구축 + 주소 교체) 0원 · 내 계정에 아무것도 안 남음

①로 시작해서 나중에 ②·③으로 올라가도 된다 — 순서 의존성 없음. 다만 ①을 오래 방치하면 개인 카드로 계속 결제되니 넘기는 날 A(5분)까지는 같이 끝내는 걸 권한다.
