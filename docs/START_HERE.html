MIDAS DRS(AX Design Generator) — 자료를 넣으면 AI가 PPT 장표·랜딩 웹사이트·eDM을 회사 스타일로 만들어 주고, 그 자리에서 편집·번역·PPTX 파일 내려받기까지 되는 웹 도구입니다. 코드를 몰라도 됩니다. 그리고 이 한 페이지가 세팅의 전부입니다 — 위에서 아래로, 나오는 순서 그대로 따라 하면 끝납니다. 앞뒤로 오갈 필요 없습니다.

먼저 알아둘 것 — AI는 지금 꺼져 있습니다
이 폴더에는 API 키가 들어 있지 않습니다. (API 키 = AI 회사에서 발급받는 이용권 번호. 이게 있어야 AI를 부를 수 있고, 쓴 만큼 그 번호로 요금이 청구됩니다.)
전달자가 일부러 자기 AI 연결을 끊고 넘겼기 때문입니다 — 안 끊으면 여러분이 테스트할 때마다 전달자 카드로 결제되니까요. 아래 2단계에서 임시로 살려 볼 수 있고, 4단계 탑재로 정식으로 켭니다.

이 문서는 아래 순서 그대로 쓰여 있습니다. 지금 몇 단계인지만 기억하면 됩니다.

1단계 · 일단 열어보기 (0분)

1 0분 · 준비물 없음

AI 없이 화면부터 구경하기

AI가 꺼져 있어도 기존 프로젝트 열람·편집·PPTX 내려받기·스타일 구경은 전부 됩니다.

방법 A (가장 쉬움) — app/index.html 파일을 더블클릭해서 브라우저로 열기. 끝입니다. (구경하고 가볍게 쓰는 데는 이걸로 충분합니다. 단점은 딱 둘 — ①파일을 고쳐도 브라우저가 옛 파일을 기억해서 강력 새로고침 ⌘+Shift+R이 필요하고 ②PDF 첨부 읽기가 일부 브라우저의 보안 제한에 걸릴 수 있습니다. 그 외에는 전부 됩니다)

방법 B (계속 쓸 사람 권장) — 작은 서버를 띄워서 열기. 고친 게 항상 즉시 반영되고(캐시 없음), 첨부 읽기도 어느 브라우저에서든 안정적입니다.

  1. 터미널을 엽니다. (터미널 = 명령어를 글로 입력하는 창. 맥은 ⌘+Space → "터미널" 검색, 윈도우는 시작 메뉴에서 "PowerShell")
  2. cd 를 치고 한 칸 띄운 뒤, 이 폴더를 터미널 창에 끌어다 놓고 엔터. (폴더 경로가 자동으로 입력됩니다. 이게 "그 폴더로 이동하라"는 뜻이에요)
  3. 이어서 아래를 직접 타이핑하고 엔터: 
    python3 serve.py
  4. 터미널에 "→ 브라우저에서 이 주소를 여세요" 라는 줄이 뜹니다 — 그 주소(보통 http://localhost:4788/app/index.html)를 브라우저 주소창에 입력하세요. (localhost = 인터넷이 아니라 내 컴퓨터 안이라는 뜻입니다. 남에게 공개되지 않아요. 4788 자리를 딴 프로그램이 쓰고 있으면 자동으로 다음 번호를 잡아서 알려줍니다 — 그래서 화면에 뜬 주소를 쓰는 게 정확합니다)

명령을 친 뒤 터미널이 멈춘 것처럼 보이면 정상입니다 — 서버가 켜져 있는 상태예요. 끄고 싶으면 Ctrl+C, 다시 쓰려면 3번부터 반복하시면 됩니다.

화면이 안 바뀌면 — 브라우저가 옛날 파일을 기억하는 것입니다
브라우저는 속도를 위해 한 번 본 파일을 저장해 둡니다(캐시). 그래서 파일을 고쳐도 화면이 그대로일 때가 있어요. 강력 새로고침으로 지웁니다 — ⌘+Shift+R (윈도우는 Ctrl+Shift+R).

정식 세팅 전에, 오늘 바로 돌려보기

이건 맛보기용 임시 연결입니다 — 키가 이 브라우저 안에만 저장되니까요. 정식 경로는 4단계 「AI 탑재」이고, 그건 이따 해도 됩니다.
  1. console.anthropic.com 에서 API 키를 발급받습니다 (sk-ant-로 시작하는 긴 문자열). 결제 수단 등록이 필요하고, 쓴 만큼 청구됩니다. (회사 도입이면 가입 대신 플랫폼개발팀에 발급 요청)
  2. 앱 왼쪽 메뉴 → 설정 → AI 생성 → 첫 번째 칸(API 키)에 붙여넣고 저장.
  3. (선택) 이미지 생성도 쓰려면 — 같은 화면 아래쪽 구글 키 (이미지 생성 · 선택) 칸에 aistudio.google.com에서 받은 키(AIza로 시작)를 붙여넣고 저장. (자기 키로 직접 그리는 방식이라 요금도 본인 부담입니다. 안 넣으면 이미지 생성만 쉬고 나머지는 전부 동작해요)
  4. 끝입니다. 홈으로 가서 아무 자료나 넣고 PPT를 하나 만들어 보세요 — 여기까지 되면 맛보기 성공!
키는 이 브라우저 안에만 저장됩니다
입력한 두 키 모두 이 컴퓨터의 브라우저 저장 공간(localStorage)에만 들어가고, 어디로도 전송되지 않습니다. 다른 분이 쓰려면 각자 자기 키를 넣어야 하고, 컴퓨터를 바꾸면 또 넣어야 합니다 — 그래서 "임시"입니다. 키를 채팅창이나 파일에 적어 두지 마세요.

① 발표 대본 — 서버가 통제하는 전용 기능이라 중계 서버가 있어야 열립니다.

② 링크로 공유하기 — "링크 만들기"는 완성된 페이지를 서버 창고에 90일간 올려 두고 그 주소를 발급하는 일입니다. 남이 열려면 페이지가 인터넷 어딘가에 살아 있어야 하는데, 개인 모드에서는 결과물이 내 브라우저 안에만 있습니다 — 남이 내 브라우저에 접속할 방법은 없죠. 그래서 키를 아무리 잘 넣어도 해결되지 않고, 창고를 가진 서버(=탑재)가 있어야 열립니다.

반대로 이미지 생성은 키 문제라서 개인 모드에서도 구글 키만 넣으면 풀립니다 — 위 표의 △가 그 뜻입니다.

즉 오늘 급한 확인은 2단계로 충분하지만, 서비스로 쓰려면 4단계 탑재가 정답입니다. 그 전에 3단계에서 클로드부터 붙입니다 — 탑재에서 파일 고치는 일을 전부 그가 대신하거든요.

파일 고치는 일을 대신해 줄 AI 비서

이 프로젝트는 디자이너가 클로드(Claude Code)에게 한국어로 요청해서 만들어졌고, 같은 방식으로 이어가면 됩니다. 다음 4단계에서 파일을 고치는 대목이 두 번 나오는데 전부 클로드가 대신합니다 — 그래서 탑재보다 먼저 붙여 둡니다.
  1. 🌐 claude.com/claude-code에서 Claude Code(클로드 작업 앱)를 내려받아 설치하고, Claude 계정으로 로그인합니다.
  2. 💬 클로드를 이 폴더에서 켭니다 — 앱이면 이 폴더를 열고, 터미널이면 cd로 이 폴더에 이동한 뒤 claude 입력. (폴더 안에 규칙서(CLAUDE.md)와 작업 절차서가 이미 들어 있어서, 이 폴더에서 켜야 자동으로 읽고 그 규칙대로 일합니다)
  3. 💬 첫 마디는 이렇게:
    "docs/HANDOVER.html이랑 CLAUDE.md 읽고 이 프로젝트 파악해줘."
  4. 💬 규칙 선언도 한 번:
    "git 푸시는 내가 말할 때만 해줘. 그리고 API 키는 나한테 절대 물어보지 마."

그 뒤로는 이런 식으로 말하면 됩니다. 개발 용어를 쓸 필요는 없습니다 — 원하는 결과와 조건만 말하면 돼요.

"이 PDF 스타일 그대로 새 PPT 팩 만들어줘. 소스에 있는 것만, 추측 금지."
"영어로 바꿨는데 버튼에 한국어가 남아 있어." — 증상만 말하면 원인을 찾아 줍니다
"방금 고친 거 실제로 되는지 검증해줘." — "될 겁니다"로 끝내지 않고 증거를 가져옵니다

더 많은 예문과 배경은 인수인계 문서(docs/HANDOVER.html)의 §3 인계자 가이드에 있습니다.

4단계 · AI 탑재 — 이 서비스의 정식 경로 (메인 · 30~40분)

여기가 본 궤도입니다. 2단계는 내 브라우저에만 사는 임시 연결이었고, 탑재는 서비스 자체가 AI를 갖게 만드는 작업입니다. 한 번 해 두면 그 뒤로는 아무도 키를 만질 일이 없습니다.

2단계와 뭐가 다른가요? — "입력"과 "탑재"의 차이
2단계(입력)는 키를 내 브라우저에만 기억시키는 방식입니다. 컴퓨터를 바꾸거나 다른 사람이 쓰면 각자 또 입력해야 하고(그것도 키 2개를 각각), 발표 대본·공유 링크는 끝내 안 됩니다.
4단계(탑재)는 키를 서비스 자체에 심는 방식입니다. 작은 중계 서버를 하나 세우고 그 안의 금고에 키를 넣어 두면, 누가 접속하든 키 입력 없이 전 기능이 돌아갑니다. 요금은 금고에 넣은 키의 주인에게 청구됩니다.
그래서 API 키는 결국 어디에 넣는 건가요? — 자리는 딱 둘

쓰는 사람마다 각자 자기 것을 한 번씩

폴더 안 파일에는 왜 못 넣나요? 이 앱은 폴더 파일이 접속자 모두의 브라우저로 배달되는 구조라, 키를 파일에 적는 순간 누구나 열람 가능한 공개물이 됩니다. 폴더를 전달·백업할 때 키가 같이 딸려가는 문제도 있고요. 비유하면 폴더=전단지, 브라우저 저장=내 지갑, 서버 금고=은행 금고 — 키는 지갑이나 금고에만 둡니다.

"파일 열어서 거기 복붙 막 하기도 하던데, 그건 뭐예요?"

① 이 절차에서 파일에 붙여넣는 건 "키"가 아니라 "주소·번호"입니다. 계정 번호, 보관함 id, 서버 주소 — 전부 어디로 찾아가라는 안내일 뿐이에요. 택배 상자에 내 집 주소 라벨을 붙이는 것과 같습니다. 비밀이 아니니 파일에 적혀 있어도 안전합니다. 게다가 직접 파일을 열 필요도 없어요 — 클로드에게 "YOUR_ 자리 채워줘"라고 말하면 대신 해 줍니다(아래 8·12번).

② 유튜브·강의에서 보는 ".env 파일에 API 키 붙여넣기"는 다른 체질의 프로젝트 이야기입니다. 그런 프로젝트는 서버에서만 도는 구조라 파일이 사용자에게 배달되지 않습니다 — 그래서 키를 파일에 적어도 됐던 거예요. 반면 이 앱은 폴더가 접속자 브라우저로 통째로 배달되는 체질이라, 같은 방식을 쓰면 키가 그대로 공개됩니다. 그래서 Cloudflare 금고(secret)를 씁니다.

③ 외울 건 한 줄입니다 — 붙여넣는 게 "주소"면 파일 OK, "키"면 금고만.

Deployed + 주소 한 줄이 보이면 성공입니다. 이 주소를 복사해 두세요 — 12번에서 씁니다. (브라우저로 그 주소를 열면 흰 화면이나 에러 문구가 나오는데 정상입니다. 사람이 보는 화면이 아니라 앱이 부르는 창구예요)
막히면

11 ⌨️ 터미널

금고에 API 키 넣기

이 문서의 핵심 한 걸음입니다. 3번에서 받은 키가 서버 금고로 들어가고, 그 뒤로는 아무도 키를 만질 일이 없습니다.

무엇을 — 아래를 치고 엔터. 한 번에 하나씩 합니다.

npx wrangler secret put ANTHROPIC_API_KEY

화면에는 — 입력을 기다리며 커서가 멈춥니다. 여기에 Claude 키를 붙여넣고 엔터하세요. 붙여넣어도 화면에 아무것도 안 보이는 게 정상입니다(비밀이라 가려짐).

✔ Enter a secret value: … ›
🌀 Creating the secret for the Worker "webgen-ppt-proxy"
✨ Success! Uploaded secret ANTHROPIC_API_KEY

이미지 생성도 쓸 거면 Gemini 키도 같은 방식으로 한 번 더:

npx wrangler secret put GEMINI_API_KEY
성공 확인
✨ Success! Uploaded secret … 이 뜨면 금고에 들어간 것입니다. (눈으로 다시 확인하고 싶으면 🌐 dash.cloudflare.com → Workers & Pages → webgen-ppt-proxy → Settings → Variables and Secrets. 이름만 보이고 값은 영영 안 보입니다 — 그게 금고의 역할입니다)
막히면
붙여넣기가 꼬여 앞뒤에 공백이나 줄바꿈이 딸려 들어가면, 나중에 생성할 때 "키가 틀렸다"는 오류가 납니다. 같은 명령을 다시 실행해 덮어쓰면 되니 부담 갖지 마세요. (구글 키는 선택 — 안 넣으면 이미지 생성만 꺼지고 나머지는 전부 동작합니다. 여기 금고에 넣어 두면 접속자 전원이 이미지 생성을 쓰게 되고, 각자 자기 설정 화면에 넣어 쓰는 방법도 그대로 남아 있습니다)
12 💬 클로드에게

앱과 서버 연결하기

앱에게 "이제부터 이 주소한테 물어봐"라고 알려 주는 단계입니다. 앱에서 고치는 자리는 이 한 곳뿐입니다.

var PROXY_URL = '';                                          ← 고치기 전

5단계 · 내 GitHub에 올리기 (선택)

이 폴더에는 버전 관리(git) 연결이 없습니다 — 전달자의 GitHub 계정과 작업 이력이 전부 제거된 순수 파일 뭉치입니다. (버전 관리 = 작업을 저장해 두고 언제든 그 시점으로 되돌릴 수 있게 하는 것. 게임 세이브와 비슷합니다.) 시작하고 싶으시면 본인 계정으로 새로 연결하세요. 클로드에게 이렇게 말하면 같이 해 줍니다:

"이 폴더 git 시작하고 내 GitHub에 새 저장소로 올리는 것 도와줘."

직접 하시려면: git init → GitHub에서 새 저장소 만들기 → 안내대로 연결. 올리는 계정과 작성자 이름은 전부 본인 컴퓨터 설정을 따릅니다. 연결한 직후 git config core.hooksPath .githooks 한 줄을 실행해 두면 저장할 때마다 자동으로 오류를 잡아 주는 검수기도 켜집니다.

부록 B · 막히면

  • 탑재(4단계) 중에 막혔을 때 — 각 카드 맨 아래 "막히면" 칸을 먼저 보세요. 거기 없는 증상이면 터미널에 뜬 빨간 글씨를 그대로 복사해 클로드에게 보여 주면 됩니다. (해석해서 설명하려 애쓰지 마세요 — 원문 그대로가 가장 정확한 정보입니다)
  • 터미널: No such file or directory — 폴더로 이동하기 전에 명령을 친 것입니다. 순서가 중요합니다: cd +폴더 끌어놓기+엔터를 먼저, 그다음 명령. (터미널 줄 앞에 폴더 이름이 보이면 이동에 성공한 상태입니다)
  • 터미널: bad pattern: [200~… — 붙여넣기가 꼬여서 명령 앞뒤에 쓰레기 글자가 붙은 것입니다. 붙여넣기 대신 손으로 직접 타이핑하면 됩니다(명령이 짧아서 금방입니다).
  • AI 생성이 안 될 때 — 설정 화면부터 보세요. "✅ 팀 공용 AI"가 떠 있으면 탑재는 된 상태이니 금고의 키(11번)를 의심하고, 키 입력칸이 보이면 아직 2단계 상태입니다. 글은 되는데 이미지만 안 되면 그건 구글 키 문제입니다 — 팀 모드면 금고의 GEMINI_API_KEY, 개인 모드면 설정 화면의 구글 키 칸을 확인하세요. 그다음 클로드에게 "생성이 안 돼"라고 증상만 말하면 원인을 찾아 나갑니다. 추측해서 설명할 필요 없습니다.
  • 화면이 안 바뀔 때 — 강력 새로고침(⌘/Ctrl+Shift+R). 브라우저가 옛 파일을 기억하고 있는 경우가 대부분입니다.
  • 저장(커밋)이 막힐 때 — 자동 검수기가 문제를 잡아낸 것입니다. 고장이 아니라 정상 동작이에요. 터미널에 뜬 메시지를 그대로 클로드에게 보여 주면 고쳐 줍니다. (폴더를 내려받은 직후에는 git config core.hooksPath .githooks 를 1회 실행해 두세요.)
  • 그 밖에 뭐가 이상할 때 — 클로드에게 그냥 보이는 대로 말하세요. "글자가 얇아 보여", "이미지가 사라졌어" 같은 말이면 충분합니다.
